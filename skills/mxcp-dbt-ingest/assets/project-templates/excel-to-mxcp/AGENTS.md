# AGENTS.md

## Project Overview

This is an MXCP (Model Context Protocol eXtension Platform) server project. MXCP is an enterprise framework for building production-ready AI tools using SQL and Python endpoints backed by DuckDB.

Configuration lives in `mxcp-site.yml` (project definition) and `mxcp-config.yml` (runtime/deployment config). dbt is enabled for data transformation.

Naming convention: projects are named `<project_name>-mxcp-server`.

## Project Structure

```
mxcp-template/
├── mxcp-site.yml       # Project configuration (required)
├── mxcp-config.yml     # Runtime/deployment configuration
├── dbt_project.yml     # dbt project config (generated by mxcp dbt-config)
├── profiles.yml        # dbt connection profiles (generated by mxcp dbt-config)
├── Dockerfile          # Container build (based on ghcr.io/raw-labs/mxcp)
├── .dockerignore       # Docker build exclusions
├── .github/workflows/  # CI/CD (tests + build/push)
├── tools/              # Tool definitions (.yml)
├── resources/          # Resource definitions (.yml)
├── prompts/            # Prompt definitions (.yml)
├── sql/                # SQL implementations
├── python/             # Python implementations
├── models/             # dbt models (staging/, intermediate/, marts/)
├── source_files/       # Raw source data files
├── .claude/skills/     # Claude Code skills (detailed guides)
├── evals/              # LLM evaluation tests
├── data/               # DuckDB database (auto-managed)
├── drift/              # Drift detection snapshots
├── audit/              # Audit logs
└── plugins/            # MXCP plugins
```

## Skills (Detailed Guides)

The `.claude/skills/` directory contains Claude Code skills with detailed reference guides. Skills auto-invoke when working on relevant files, or can be triggered manually via `/skill-name`.

| When working on... | Skill (auto-invokes) |
|---------------------|------------|
| dbt models (`models/`) | `.claude/skills/dbt/SKILL.md` |
| Tool/resource/prompt YAML (`tools/`, `resources/`, `prompts/`) | `.claude/skills/endpoints/SKILL.md` |
| SQL endpoints (`sql/`) | `.claude/skills/sql/SKILL.md` |
| Python endpoints (`python/`) | `.claude/skills/python/SKILL.md` |

## Validation Rules — ALWAYS Follow

After **every** change to any YAML, SQL, Python, or dbt model file, you **must** run all three commands in this order:

```bash
mxcp validate
mxcp lint
mxcp test
```

Do not consider work complete until all three pass. If any command fails, fix the issue before moving on.

- `mxcp validate` — checks structural correctness of all definitions
- `mxcp lint` — checks metadata quality (descriptions, examples, types) for LLM consumption
- `mxcp test` — runs all endpoint tests defined in YAML files

When dbt models are changed, also run:

```bash
mxcp dbt run
mxcp dbt test
```

## Endpoint Conventions

- **Tools** go in `tools/*.yml` — use for actions and queries
- **Resources** go in `resources/*.yml` — use for URI-based data access
- **Prompts** go in `prompts/*.yml` — use for reusable message templates
- SQL implementations go in `sql/`, Python in `python/`
- Source files are referenced from YAML via relative paths (e.g., `file: ../sql/my_query.sql`)

## YAML Schema

Every YAML file starts with `mxcp: 1`. Valid parameter types: `string`, `number`, `integer`, `boolean`, `array`, `object`.

Every tool/resource/prompt must have:
- A clear `name` in `snake_case`
- A `description` explaining purpose, when to use it, and what it returns
- Parameters with `description`, correct `type`, and `examples`
- A `return` block documenting the output structure
- At least one test case under `tests`

## dbt

dbt is enabled in this project. Models go in `models/` following the layered pattern:

- `models/staging/` — raw data cleanup
- `models/intermediate/` — business logic joins and transforms
- `models/marts/` — final AI-ready models

MXCP endpoints query dbt models directly by table name. After modifying models, run `mxcp dbt run` then `mxcp dbt test` before running `mxcp validate`.

## DuckDB

MXCP uses DuckDB as its database engine. The default database is auto-managed at `data/db-default.duckdb`. Do not configure a custom database path unless explicitly asked. DuckDB can read CSV, Parquet, and JSON files directly with `read_csv_auto()`, `read_parquet()`, `read_json_auto()`.

## Security

Never write custom authentication code. MXCP provides built-in OAuth, CEL policies, and user context functions (`get_username()`, `get_user_email()`). Only add security features when explicitly requested.
